# Off-repo GeoJSON data (`data.bikenetkit.org`)

> **Maintainers only — needs SSH access to the server** for § Uploading, § nginx and the server
> checks in § Verifying. The rest describes how the build and the app use the data, and applies
> to any checkout.

> **Placeholders.** `<SERVER_IP>` and `<SSH_USER>` stand in for values kept out of this
> repository; substitute your own. The maintainers (listed in
> [.github/CODEOWNERS](../.github/CODEOWNERS)) hold the real values.

The per-city tool layers (`www/data/`) are served as **plain static GeoJSON from the project's
own server**, not committed to git. They are several GB and grow with the city catalogue, which
would otherwise bloat the repo, its history on every data refresh, and every clone.

Like the basemap, there is no API key and no third-party service in the runtime path, so the data
fits the goal of running for years without maintenance.

## How the pieces fit

- **The build never reads or ships the data.** `www/data/` is gitignored and sits _outside_
  `static/`, so Vite's public-dir copy never duplicates it into `build/`. The app enumerates
  datasets from the committed [src/lib/data/data-files.json](src/lib/data/data-files.json)
  manifest (generated by `update-data`; parsed by
  [src/lib/data/datasets.ts](src/lib/data/datasets.ts)), and fetches the GeoJSON in the browser at
  runtime.
- **`PUBLIC_DATA_URL`** prefixes every data fetch (via `dataUrl()` in
  [src/lib/data/data-base.ts](src/lib/data/data-base.ts), used by `tool-paths.ts` and
  `boundaries.ts`). Empty means same-origin `/data/…` (local dev); an absolute URL means the data
  host, which serves the data directory at its root.
- **One endpoint, all environments.** A cross-origin `GET` for GeoJSON is a CORS _simple request_
  (no preflight), so pointing every deployed environment at `data.bikenetkit.org` costs nothing
  measurable.
- **Per-dataset screenshots ride the same host** under `/screenshots` (also gitignored, in
  `www/screenshots/`). `screenshotFor()` in `tool-paths.ts` routes them through the same
  `dataUrl()`, which resolves them to `${PUBLIC_DATA_URL}/screenshots/…`. `pnpm deploy:data`
  uploads `www/screenshots/` alongside the GeoJSON. Regenerate them with
  `pnpm generate:screenshots`, which captures against `pnpm preview` and builds first if nothing
  answers on its port.
- **So do the per-city Open Graph cards**, under `/screenshots/og/`. `pnpm generate:og-cards`
  captures them into `www/screenshots/og/` and rewrites the committed `src/lib/data/og-cards.json`,
  which is what lets a page use its card: an unlisted card falls back to the tool's own. The cards
  ride the screenshot sync, so **run `pnpm deploy:data` before the site deploy that commits a newer
  manifest**, or the new pages preview with an image the data host does not have yet.
  `pnpm check:og-cards` compares the manifest with the files on disk. The cards are JPEG, not
  WebP, so the vhost needs its own `\.jpg$` location (§ nginx); without it every card 404s while
  the files sit on the server.

| Environment                          | `PUBLIC_DATA_URL`                                    |
| ------------------------------------ | ---------------------------------------------------- |
| Production (`bikenetkit.org`)        | `https://data.bikenetkit.org` (forced by the deploy) |
| Preview host (`pnpm deploy:preview`) | `https://data.bikenetkit.org` (forced by the deploy) |
| Local dev                            | _(empty)_ → local `www/data/` via the Vite plugin    |

`www/.env` leaves `PUBLIC_DATA_URL` empty for local dev, which resolves to same-origin `/data/…`.
A deployed build cannot use that, because the site origin serves no data. So `pnpm deploy:site`,
`pnpm deploy:preview` and `pnpm deploy:placeholder` (`scripts/deploy.mjs`) all force
`PUBLIC_DATA_URL` to `DEPLOY_PUBLIC_DATA_URL` (`www/.env`, default `https://data.bikenetkit.org`)
for the build they run; no manual `www/.env` edit is needed before deploying. The placeholder
page's hero map (`AmbientMapPane.svelte`) fetches GeoJSON too, so it needs the data host just like
the full site.

## The build is independent of the data

`pnpm build` never reads a byte of GeoJSON. It needs neither `www/data/` on disk nor a reachable
`data.bikenetkit.org`, and a clean clone builds the identical set of pages.

Three things get it there:

- **The map pages fetch in the browser, not at prerender.** Their `load()` is synchronous and
  fetch-free; the layers are fetched on hydration by
  [src/lib/data/active-dataset.svelte.js](src/lib/data/active-dataset.svelte.js), owned by the
  `(map)` layout. The prerendered shell keeps its per-city title, description and panels, so
  crawlers and shared links lose nothing. `svelte.config.js`'s `handleHttpError` therefore has no
  `/data/…` branches: the prerenderer never requests a dataset.
- **The route set comes from the manifest.** `entries()` reads `data-files.json`, not a `readdir`
  of the data tree, so the prerendered pages do not depend on whether the building machine holds
  the data.
- **The data lives outside `static/`.** `www/data/` and `www/screenshots/` are served in dev and
  preview by the `offRepoData` middleware in [vite.config.js](vite.config.js), so local work stays
  offline-capable without the build copying several GB into `build/` on every run.

**Two invariants live in the build-time preflight**, the `init` hook in
[src/hooks.server.ts](src/hooks.server.ts), where they fail in seconds, before the prerender,
rather than mid-crawl on a 404:

- a tool the manifest lists no datasets for;
- a LinkBikeNet city missing its **mandatory** existing-network baseline. (FixBikeNet's baseline is
  optional per city.)

> The root [src/routes/+layout.ts](src/routes/+layout.ts) carries `export const prerender = true`,
> which every other route inherits. Removing it un-prerenders the entire map section, and the
> build still goes green. It is a universal file on purpose: a `+layout.server.ts` on the root
> layout, even one without a `load`, makes the client fetch `__data.json` before every route, and
> the client-only `/embed` then 404s on a static host.

## Refreshing the data

The runbook (pull, check, upload, compress, commit, deploy) is
[README.md](../README.md#for-maintainers-updating-the-data) § For maintainers: updating the data.
Two facts that matter here: the run rewrites `data-files.json` from the **complete** `www/data/`
tree, so a filtered `--tool` run never drops a tool; and
`node scripts/update-data.mjs --boundaries-only` refreshes only the simplified city boundaries
and the manifest, reading `www/data/` rather than an export.

## Uploading

```sh
pnpm deploy:data -- --dry-run
pnpm deploy:data
pnpm deploy:data -- --force   # mirror www/screenshots/ exactly even when sparse (see below)
pnpm compress:data            # then rebuild the .gz/.br siblings on the server
```

`deploy:data` rsyncs `www/data/` to `DEPLOY_DATA_WEB_PATH` (default `~/bikenetkit/data/`), a
sibling of the website directory ([OPERATIONS.md](../OPERATIONS.md) § Server layout). It uses
`--delete` within that directory, so the served data stays an exact mirror of `www/data/` and
stale cities and layers are pruned. That includes `www/data/context/`, the rail station and school
points written by `pnpm import:context` (which `pnpm pull-data` runs). Because a mirror without
them would delete them from the data host, `deploy:data` aborts when `www/data/context/` is
missing or empty.

Run `pnpm compress:data` after every upload. Until it has run, the new files have no `.gz`/`.br`
siblings and nginx falls back to compressing them per request (§ nginx). Then commit
`src/lib/data/` (the regenerated manifests) and deploy the site, so the build matches the uploaded
data.

### Screenshot coverage guard

Unlike `www/data/`, `www/screenshots/` is generated locally over hours
(`pnpm generate:screenshots`), not pulled from the server export; a fresh checkout seeds it from
the data host with `pnpm pull-screenshots` (below). Every run of `deploy:data` prints a coverage
report ([scripts/screenshot-coverage.mjs](scripts/screenshot-coverage.mjs)): a total line and one
line per tool, present against expected. The expected set is the city × metric × type × variant
matrix `generate:screenshots` iterates, read from the committed `data-files.json` manifest rather
than from `www/data/`, so a fresh checkout without the data still gets a meaningful number.

- **100% coverage**: synced as normal, with `--delete` (exact mirror).
- **Below 100%, at or above 90%**: a one-line note; synced with `--delete` (a few stragglers during
  otherwise-finished generation are expected).
- **Below 90% ("sparse")**: a WARNING, and the sync drops `--delete`. It becomes purely additive,
  so a partial local set can never prune screenshots already on the server. Pass `--force` to
  mirror exactly anyway (the server ends up matching this partial set).
- **Zero screenshots present**: the screenshot sync is skipped entirely (nothing to add, and an
  empty tree must not touch the server's existing set).

**A fresh checkout starts at 0%.** Run `pnpm pull-screenshots` once before generating anything: it
fetches the server's set, OG cards included, into `www/screenshots/`. It only adds (no `--delete`,
and `--update` keeps any local image newer than the server's copy), so it is also safe to re-run
on a checkout that has unuploaded screenshots. Without it, `generate:og-cards` rewrites
`og-cards.json` from the few cards that exist locally.

The GeoJSON sync above is never gated by this check.

Non-`.geojson` files under `www/data/` (the `cities/*.csv` metadata files) ride along in the rsync
but are never fetched at runtime; the vhost's `location / { return 404; }` makes them inert.

## nginx

A dedicated vhost for `data.bikenetkit.org` serving `~/bikenetkit/data/`. Unlike the tiles vhost,
gzip is **on**: GeoJSON compresses several times over. The per-dataset screenshots live under
`/screenshots/` in the same directory and are served by their own `location`s (WebP and JPEG are
already compressed, so they are left out of `gzip_types`; `<img>` loads need no CORS header).

**Serve the pre-compressed siblings, don't compress per request.** `gzip on;` on its own uses
nginx's default `gzip_comp_level 1`, the weakest setting, and pays that CPU on every request.
`pnpm compress:data` writes `.gz` and `.br` next to each `.geojson` on the server, and
`gzip_static` / `brotli_static` hand them straight out. On the largest layer, the brotli sibling
is about 40% smaller than nginx's default on-the-fly gzip, and costs no CPU per request.

`gzip_static` is in nginx core. `brotli_static` comes from a module package, and on Ubuntu 26.04
the brotli support is **split in two**; there is no `libnginx-mod-http-brotli`:

```sh
sudo apt install brotli \
  libnginx-mod-http-brotli-filter \
  libnginx-mod-http-brotli-static
```

`-static` is the one that provides `brotli_static`; `-filter` provides on-the-fly `brotli` and is
not strictly needed here, but installing both keeps the directive set complete. Installing them
drops `50-mod-http-brotli-*.conf` into `/etc/nginx/modules-enabled/`, so no `load_module` line is
needed. **Without the module, `brotli_static on;` makes nginx fail to start**: install first,
`sudo nginx -t`, then reload. If it is unavailable, drop that line and keep `gzip_static` alone;
`compress-data.mjs` likewise skips `.br` when the `brotli` CLI is missing.

Keep `gzip on;` below as the fallback for anything without a sibling (a dataset uploaded but not
yet compressed). `gzip_static always;` is deliberately not used, since that would serve a stale
`.gz` in preference to a newer source.

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name data.bikenetkit.org;

    root /home/<SSH_USER>/bikenetkit/data;

    # Security headers (DEPLOY_NGINX.md § Security headers), repeated in every location below:
    # each sets its own add_header, which discards the server-level ones.
    include snippets/bikenetkit-security.conf;

    # Truncate the client IP before it is logged, like the site vhost. The format is defined in
    # conf.d/anonymized-log.conf — see DEPLOY_NGINX.md; the privacy notice at /legal#privacy says
    # no full address is stored anywhere, and that has to hold on this host too. A log of its own,
    # so data requests never count as page views (DEPLOY_STATS.md).
    access_log /var/log/nginx/data.access.log anonymized;

    # Prefer the pre-compressed siblings written by `pnpm compress:data`. Drop the brotli_static
    # line if libnginx-mod-http-brotli-static is not installed — nginx refuses to start without it.
    gzip_static on;
    brotli_static on;

    # Fallback for anything with no sibling yet. Level 6 rather than the default 1: the default
    # leaves ~20% on the table, and this path should be rare once compress:data has run.
    gzip on;
    gzip_comp_level 6;
    gzip_types application/geo+json application/json;
    gzip_min_length 1024;

    location ~ \.geojson$ {
        include snippets/bikenetkit-security.conf;
        default_type application/geo+json;

        add_header Access-Control-Allow-Origin  "*" always;
        add_header Access-Control-Allow-Methods "GET, HEAD, OPTIONS" always;

        # A refresh rewrites files in place under the same names, so a modest TTL rather than
        # immutable: a refresh reaches every visitor within the hour.
        add_header Cache-Control "public, max-age=3600" always;

        if ($request_method = OPTIONS) { return 204; }

        try_files $uri =404;
    }

    # Per-dataset preview screenshots (pushed to /screenshots/ by `pnpm deploy:data`). Loaded via
    # <img>, so no CORS header is needed; already-compressed webp is not gzipped.
    location ~ \.webp$ {
        include snippets/bikenetkit-security.conf;
        default_type image/webp;
        add_header Cache-Control "public, max-age=3600" always;
        try_files $uri =404;
    }

    # Per-city Open Graph cards (pushed to /screenshots/og/ by `pnpm deploy:data`). Fetched by
    # social crawlers, so no CORS header; already-compressed jpeg is not gzipped.
    location ~ \.jpg$ {
        include snippets/bikenetkit-security.conf;
        default_type image/jpeg;
        add_header Cache-Control "public, max-age=3600" always;
        try_files $uri =404;
    }

    location / { return 404; }
}
```

```sh
sudo ln -sf /etc/nginx/sites-available/bikenetkit-data /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d data.bikenetkit.org
```

`data.bikenetkit.org` resolves through the zone's wildcard record
([DEPLOY_NGINX.md](DEPLOY_NGINX.md) § DNS), so certbot can issue the certificate as soon as this
vhost answers on port 80.

## Verifying

**Locally**, without uploading: serve `www/data/` cross-origin and point the app at it.

```sh
npx --yes http-server data -p 8082 --cors
# www/.env: PUBLIC_DATA_URL=http://localhost:8082
pnpm build && pnpm preview
```

Open an interactive tool page and confirm the map layers and city boundaries load from
`localhost:8082` (cross-origin 200s in devtools). With `PUBLIC_DATA_URL` **empty**, the same pages
must load from local `www/data/` via the `offRepoData` middleware, in both `pnpm dev` and
`pnpm preview`.

**Clean build**: move `www/data/` away and build with `PUBLIC_DATA_URL` unset. It must
**succeed**, since nothing is fetched at prerender, so neither the files nor a reachable host is
required. Confirm the output carries no data at all:

```sh
ls build | grep -E '^(data|screenshots)$'      # expect no output
grep -c coordinates build/growbikenet/<city>/<metric>/<type>/<variant>.html   # expect 0
find build/growbikenet -name '*.html' | wc -l  # unchanged with the data absent
```

That last count is the point of enumerating from the manifest: the prerendered route set does not
depend on whether the building machine happens to hold the data.

**The server**, with CORS and compression:

```sh
curl -sI -H 'Accept-Encoding: gzip' \
  https://data.bikenetkit.org/cities/amsterdam_nl-boundary.geojson
# expect: 200, Access-Control-Allow-Origin: *, Content-Encoding: gzip
```

**The pre-compressed siblings**: after `pnpm compress:data`, confirm the static variants are the
ones being served.

```sh
# brotli_static: expect Content-Encoding: br
curl -sI -H 'Accept-Encoding: br' \
  https://data.bikenetkit.org/superblockify/berlin_de-residential-edges.geojson

# gzip_static: expect Content-Encoding: gzip
curl -sI -H 'Accept-Encoding: gzip' \
  https://data.bikenetkit.org/superblockify/berlin_de-residential-edges.geojson
```

Compare each `Content-Length` with the size of the `.br` or `.gz` file next to the source on the
server. A compressed response with no `Content-Length`, or a larger one, means nginx is
compressing per request: check that the sibling exists and that the module is loaded.

On a new server that has no certificate yet, the same checks work over plain HTTP: add
`--resolve data.bikenetkit.org:80:<SERVER_IP>` and use `http://`. Once certbot has run, port 80
only redirects.
